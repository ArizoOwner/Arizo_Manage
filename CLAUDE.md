## Security invariants (never regress)
1. **CSP** in `index.html` is the PROMPT.md §1.2 policy plus tightening, plus one documented addition: `script-src 'self' 'wasm-unsafe-eval'` (required to instantiate the Argon2id WASM; it allows WebAssembly compilation only, not JS `eval`). Pinned by `tests/csp.test.ts`. No remote origin, ever.
2. **No inline scripts** in built HTML. Capacitor injects its bridge via `addDocumentStartJavaScript` on modern WebViews; on very old WebViews it falls back to inline injection, which the CSP blocks. **Still to verify on a real device.**
3. **Zero network**: no CDN, no telemetry, no Firebase (google-services removed from Gradle). `MainActivity.FirewallWebViewClient` answers every non-`https://localhost` request with 403 and refuses navigation away. E2E asserts zero external requests on web.
4. **Android manifest**: `allowBackup=false`, `fullBackupContent=false`, `dataExtractionRules` exclude all, `usesCleartextTraffic=false`, `network_security_config.xml` forbids cleartext. `FLAG_SECURE` set in `onCreate`; only `ArizoSecurity.setScreenshotAllowed({allowForMs ≤ 120000})` lifts it temporarily.
5. **Money** is `bigint` minor units end to end (schema, ledger, codec). `src/core/currency/money.ts` has no float math.
6. **Never log** secrets: `SecureLogger` is a no-op in production and redacts in dev. Production builds drop every `console.*` (`esbuild.drop` in `vite.config.ts`; i18next `showSupportNotice: false`); `check-prod.mjs` allows only Capacitor's bridge `win.console.error` and Workbox's sw `console.warn`. R8 strips `android.util.Log` in release.
7. **DEK handling**: Android DEK exists only in native memory (`ArizoSecurityPlugin` → `ArizoSqlCipherPlugin.takeDek()`, zeroized after keying). Web CryptoKeys are non-extractable; raw bytes are zeroized after import; the crypto worker is terminated on lock.
8. **Record AAD**: every web ciphertext is bound to `arizo/rec/v1|<store>|<id>`, so rows cannot be swapped or moved. Tested.
9. **SMS firewall first**: OTP/2FA and promo messages are rejected before anything else and are never written anywhere (no transaction, no inbox entry, no audit row). Native `SmsFilter` drops them before sealing; `firewall()` drops them again in JS. Pinned by `tests/sms-parser.test.ts` ("never persisted anywhere").
10. **SMS text** never reaches a log, a notification or the URL: the capture notification is generic (`capture_text`, `VISIBILITY_PRIVATE` plus a public version), `#/sms-ingest?d=` is replaced with `#/sms` by the first import of `main.tsx` (before the router reads the URL), and queue items open only through `ArizoSecurity.openQueueItem` (refuses while locked). Nothing is ingested into a decoy session.
11. **Analytics never counts a transfer**: income/expense = posted, not trashed, `type` income|expense only (same rule as `cashflowInBase`); splits count per split category; foreign amounts convert with manual rates only and missing rates are listed (`missingRates`), never guessed. Pinned by `tests/analytics.test.ts`. The analytics worker is terminated on lock and wipe.
12. **Attachments are encrypted at rest**: web blobs live in the Dexie `blobs` table (v2) as AES-256-GCM under the vault `blob` key with AAD `arizo/blob/v1|<id>` (moved or tampered blobs fail); Android blobs live in the SQLCipher table `vault_blobs` (migration 2). Image type is sniffed from magic bytes (PNG/JPEG/WebP only, at most 2 MB); the row keeps the plaintext SHA-256, checked on every read. Decrypted images exist only as in-memory data URLs. Pinned by `tests/invoices.test.ts`.
13. **Exports leave the vault only on purpose**: every print/PNG/xlsx/csv/thermal action needs a fresh PIN (`useReauth`) and is refused while stealth blur is on (the hidden print copy is not even mounted then). Android writes the file to the app cache only for the share sheet and deletes it in `finally`. CSV text cells starting with `= + - @` get a leading `'` (formula injection); plain signed numbers stay raw.
15. **Backups are zero-knowledge and tamper-evident**: a `.arizo` file is AES-256-GCM under a random file key, wrapped per slot (Argon2id of the passphrase; HKDF of the Recovery Key); the whole header is the body AAD and its fixed part is each slot's AAD, so any bit flip, a wrong secret or truncation fails before anything is written. Creating and restoring need re-auth; audit rows say only `file`/`file+recovery`/`replace`/`merge`. Backup bookkeeping (`settings.backup_state`, `backup_snapshots`) never travels in a file and is never overwritten by a restore. Pinned by `tests/backup.test.ts`.
14. **One socket, LAN only**: `ArizoThermalPrintPlugin` opens raw TCP only to a literal private IPv4 (10/8, 172.16/12, 192.168/16, 169.254/16; no hostnames, so no DNS) or RFCOMM to an already-paired printer. `BLUETOOTH_CONNECT` is requested only when the user turns thermal printing on. The WebView firewall is unchanged; JS never opens a socket.

## Architecture (Phase 1)
- `src/core/crypto/`: `bytes` (zeroize, b64, hex, constant-time compare, chunked CSPRNG), `primitives` (Argon2id m=64MiB t=3 p=1, AES-256-GCM seal/open with 96-bit nonce, HKDF-SHA256), `keyring` (DEK wrapped per PIN slot; main + decoy slots; all slots always derived so timing hides the decoy; HKDF sub-keys `record`/`blob`/`index`), `crypto.worker` + `cryptoClient` (transferable PIN buffers, terminate on lock).
- `src/core/storage/`: `schema.ts` (18 entity groups, 26 stores, `INDEXED`/`UNIQUE` maps), `IVaultDatabase` contract, `StagedVault` (shared tx core: writes staged in memory, applied as one atomic batch; reads see staged writes; nested tx joins), `WebEncryptedDexieAdapter` (rows = id + HMAC tags + AES-GCM blob), `SqlVaultAdapter` (one table per store, `ix_*` columns, UNIQUE indexes, JSON `data`; `SQL_MIGRATIONS` append-only), `codec` (lossless bigint JSON).
- `src/core/ledger/ledger.ts`: create/update/void/soft-delete/restore/post-pending, transfers (pair + optional fee sharing `transfer_pair_id`), splits (Σ = parent), `postLinkedTransaction` (one live tx per obligation), `purgeTrash` (30 d), `verifyLedger` (drift/orphans/broken pairs/split mismatches, optional fix), `incomeExpenseTotals` (transfers excluded).
- `src/core/security/`: `vaultService` (create/unlock/lock/changePin/wipe on both platforms), `lockout` (5→30 s, 8→5 m, 10→15 m, opt-in wipe at 15).
- `src/core/bridge/native.ts`: typed `ArizoSecurity` / `ArizoSqlCipher` plugins + `sqlCipherExecutor`.
- Android `plugins/ArizoSecurityPlugin.kt`: PIN slot (AES-GCM with the JS Argon2 KEK, same AAD as web), bio slot (Keystore AES, StrongBox→TEE fallback, BIOMETRIC_STRONG per use, invalidated on enrolment → `BIO_INVALIDATED`), RSA-OAEP queue keypair + `sealForQueue` (for Phase 5 receivers) + `openQueueItem` (unlocked only), sensitive clipboard (45 s), FLAG_SECURE toggle.
- Android `plugins/ArizoSqlCipherPlugin.kt`: raw 32-byte key, asserts `PRAGMA cipher_version`, WAL, `secure_delete`, `foreign_keys`; single background thread; errors never echo SQL or values.
- `src/core/data/`: `banks.json` (39 entries: 29 Iranian banks/institutions + 3 neo-banks + 7 international; all `verified: false`, senders and Android packages empty for the user to confirm), `seedCategories` (stable ids `cat_*`, idempotent).
- Validators: Luhn, Sheba mod-97, national ID (personal + legal), economic code, Sayad (shape only: no public checksum), mobile. `numToPersianWords` up to quadrillions.

## SMS engine (Phase 5)
- `src/core/sms/normalize.ts`: `normalizeSms` (Persian/Arabic digits to ASCII, ي/ى/ك, strips ZWNJ/ZWJ/RLM/LRM/bidi/tatweel, `2,000,000-` becomes `-2,000,000` without touching dates or times) and `firewall` (OTP + spam keywords, runs first).
- `src/core/data/sms-templates.json`: data-driven labels (amount/balance/ref/card/merchant), direction and channel words, 39 bank templates (detected by name keywords; Iranian banks default to Rial, international banks to their currency and date order), Persian/English merchant to `cat_*` map. No sender numbers.
- `src/core/sms/parser.ts`: `parseSms` = firewall, normalize, enabled custom rules (priority order; `field_map_json` = capture group per field; `unit_hint`, `type_hint`), then template + label-driven extraction, then a heuristic fallback (largest grouped number). Dates (Jalali `1403/08/15`, `03/08/22`, Gregorian `mdy`/`dmy`, `20-Nov-2026`, `Nov 20, 2026`) and times are blanked before amounts are looked for; masked or 16-digit cards and ungrouped runs of 10+ digits (accounts, reference ids) are never amounts. An explicit `ریال`/`تومان`/`$`/`€`/`£`/`AED` wins over the bank default (Toman x 10 = Rial). Confidence 0–1; `LOW_CONFIDENCE` 0.6. `smsFingerprint` = SHA-256 of the normalized body. `splitBulk` for paste.
- `src/core/sms/ingest.ts`: `ingestMany` (one atomic tx per message): fingerprint already stored = `duplicate`; unparsed or no matching account = inbox (`settings.sms_inbox`, max 100); account match = card suffix, else the only account of that bank, else the only bank-type account in that currency; SMS + push pair = same account and amount within 2 min with equal (or one missing) balances = `duplicate`; otherwise a `pending_review` tx with its category from `merchant_category_memory`, then the bundled map. `approvePending` posts and learns the merchant. `confirmSender` stores a user-confirmed sender-to-bank pair in `settings.sms_senders`. `balanceDrift` compares the latest reported balance with the running ledger balance at that point (a later adjustment clears it); the UI fixes drift through `reconcileBalance`. Teach: `numberTokens` + `buildTaughtRegex` (anchors on the two words before each tapped number, digits generalized). `saveRule`/`deleteRule` write `sms_parser_rules` plus an `sms_rule_changed` audit row (no content). `reprocessInbox` re-runs the inbox after any rule, sender or account change.
- `src/core/sms/sms.worker.ts` + `smsClient.ts` (`workerParser`): parsing runs off the UI thread; the worker is terminated on lock.
- `src/features/sms-intelligence/`: `intake.ts` (drains the Android sealed queue after unlock; `captureIngestFragment` runs from `src/app/bootFragment.ts`; `flushHeldFragment` after a main-vault unlock), `SmsCenter.tsx` (`#/sms`, `#/sms/paste`: Review Queue with account/category edit, flip and approve-all; Paste & Parse with a summary; Inbox with Teach and sender confirmation; drift badge with 1-tap Adjust), `Teach.tsx` (tap-to-regex with live preview; Regex Studio editor with a match count against inbox samples), `Wizards.tsx` (Android capture switches, 2-step Restricted Settings guide with Open App Info, bank-app picker, 30/90/365-day history scan; illustrated 4-step iOS Shortcuts guide with the copyable `#/sms-ingest?d=` URL).
- Dock "Paste SMS" opens `#/sms/paste`; the More "SMS Center" tile is live; the dashboard pending badge opens `#/sms`.
- Android `plugins/ArizoSmsPlugin.kt`: `BankSmsReceiver` (manifest component **disabled** until `setSmsEnabled(true)`; multipart PDUs joined per sender), `BankNotificationListener` (only `SmsPrefs.packages`), `SmsFilter` (native OTP/spam/bank-keyword gate), `SmsQueue` (sealed JSON files in `noBackupFilesDir/sms_queue`, max 2000, ids validated on delete, cleared by `destroyVault`), `CaptureNotifier` (generic, private). Methods: `status`, `setSmsEnabled` (requests RECEIVE_SMS/READ_SMS only then), `setNotificationsEnabled`, `openNotificationAccess`, `openAppInfo`, `listApps` (launcher `<queries>`, no QUERY_ALL_PACKAGES), `pending`, `ack`, `scanInbox` (background thread, at most 5000 messages). Switches live in SharedPreferences (not sensitive) because the receiver runs while the app is killed.

## Analytics, budgets & goals (Phase 6)
- `src/core/analytics/periods.ts`: `periodOf`/`periodAt`/`shiftPeriod` (Jalali or Gregorian month, half-open, Asia/Tehran midnights), `weekRange` (Sat or Mon start), `budgetRange` (`custom` follows the user's calendar month: the schema has no custom start/end), `dayStarts` (local midnights).
- `src/core/analytics/engine.ts` `computeAnalytics(input, {now, cal, y, m})`, pure, bigint: split-aware pieces (one per split, else one per tx) converted to IRR at each tx's date; cashflow + savings rate + delta vs previous period (bps); 6-month series; category tree (top level → direct children → up to 100 tx refs) for drill-down; Sankey (top 5 income cats → top 5 accounts → top 6 expense cats, tail folded into `other`); daily heatmap; net worth per day (current balances walked back through `balanceEffect`, an account counts only after `created_at`, each day at that day's rates, ending today); budgets; goals; health score; subscriptions; insights.
  - **Budget burn rate** (`budgetStatus`): today counts as elapsed; `safePerDay = remaining / daysLeft` (today included, rounded down); velocity `projected = spent × daysTotal / daysElapsed`; `alert` = highest threshold reached; rollover carries only the previous window's unused part. Category budgets include sub-categories and split pieces.
  - **Financial Health Score** (0–100, null without activity in the last 3 periods): savings rate 30 (≥ 20 % = full), emergency fund 25 (liquid ÷ average monthly expense over active periods, 6 months = full), debt load 20 (borrowed left + unpaid installments ÷ assets, 0 % full → 50 % zero), budgets 15 (share not projected over; none = 8), trend 10 (this period vs the prior periods the history covers, ≤ 100 % full → 150 % zero; none covered = 5). Linear, rounded per part.
  - **Subscription Detector**: same normalized merchant, ≥ 3 posted expenses, last ≤ 6 judged, every gap within weekly ±2 d / monthly ±4 d / yearly ±12 d, each amount within 15 % of the median, not stale (> 1.5 intervals), loan/cheque/debt/invoice postings excluded; `monthly` cost normalised.
  - **Insights** (rendered by `insight.*` in fa/en): `catUp`/`catDown` (±25 % vs the 3-month average, only when the history covers those 3 months; `catDown` only after the period ends), `overspend`, `saving` (≥ 20 %), `budgetOver`, `subs`, `missingRates`.

- `src/core/analytics/plans.ts`: `saveBudget` (limit > 0, thresholds 1–200 deduped and sorted, expense category only, one active budget per category + period + currency), `saveGoal`/`contributeGoal` (never below 0; a linked goal follows its account balance and must share its currency), `saveCategory` (one level of sub-categories of the same type; system rows keep type and parent), `deleteCategory` (soft; refuses system rows, rows with children or with a budget). ## Invoices, statements & printing (Phase 7)
- `src/core/invoices/invoices.ts`: **one rounding rule**, half-up at exactly two points: each line `qty_milli × unit_price / 1000`, and VAT `taxable × vat_bps / 10 000`; discounts, subtotal and total are integer sums of rounded values, so printed columns always add up. `computeTotals` refuses qty ≤ 0, a negative price, a line discount above its line, an invoice discount above the subtotal, and VAT outside 0–10 000 bps or non-integer. `parseQuantity` (≤ 3 decimals, Persian digits). `totalInWords` (IRR via `amountToPersianWords` in the display unit; other currencies name the fraction, e.g. صدم). Numbering `<PREFIX>-<Jalali year of issue>-<0001>` = highest sequence of that year + 1, backed by UNIQUE(`invoices.number`); edits keep the number. The business profile is one row (`id = 'main'`), IDs checked with `isValidNationalId`/`isValidLegalNationalId`/`isValidEconomicCode`, prefix 2–5 capitals, default VAT 1000 bps. A proforma stays `draft` and is never payable. `postInvoicePayment`: income in the invoice currency (the account currency must match), category `cat_business`, payee = customer, posted through `postLinkedTransaction` with `linked_entity_type 'invoice'` and `linked_entity_id '<invoice id>#<n>'` (one id per partial payment), so a repeat call or double tap returns the existing tx (`created: false`). Status unpaid → partial → paid from `paid_minor`; an invoice with payments cannot be edited or deleted; `undoLastPayment` voids the last payment tx. `qrSummary` is plain text (number, seller, code, Jalali date, total) with no URL.

## Backup & restore (Phase 8)
- `src/core/backup/container.ts`: the `.arizo` v1 binary (`ARZO` | version 1 | KDF 1 = Argon2id | m u32 BE | t u32 BE | p u8 | salt 16 | slot count | slots of kind + nonce + wrapped file key | body nonce | AES-256-GCM(gzip(payload)) with the header as AAD). `readHeader` validates shape and caps Argon2 cost (m ≤ 1 GiB, t ≤ 16, p ≤ 8) before any work; `gunzip` refuses more than 512 MiB (gzip bomb). Errors are `BackupError` codes (`BACKUP_FORMAT`/`VERSION`/`AUTH`/`NO_RECOVERY`/`TOO_LARGE`/`TOO_NEW`). Secrets are zeroized.
- `payload.ts`: `takeSnapshot` (every store in `STORE_NAMES` + every attachment blob as plaintext bytes, minus device-local backup settings) and the manifest (counts per store, app version, `SQL_SCHEMA_VERSION`, `WEB_DB_VERSION`, platform, created_at, blob count/bytes, unreadable blobs); `encodeSnapshot`/`decodeSnapshot` (lossless bigint via `storage/codec`, blobs base64; counts must match the manifest; newer schema or unknown store = `BACKUP_TOO_NEW`); `checkBlobs` (SHA-256 of every blob against its attachment row before writing).
- `restore.ts`: `replaceWith` (deletes then puts in one staged tx; blobs written before rows, put back on failure) and `mergeInto` (UUID match, newer `updated_at` wins, a tie keeps local; an incoming transaction whose `sms_fingerprint_sha256` exists locally is skipped with its splits, tags and attachments; a clashing invoice number gets `-2`, `-3`...; then `verifyLedger(fix)`).
- `service.ts`: `createBackup`, `inspectBackup` (Dry-Run: decrypt + validate, no write), `restoreBackup` (pre-restore safety snapshot first; Replace is read back and must match the counts, else it is undone), rolling snapshots (`saveSnapshot`/`loadSnapshot`/`maybeAutoSnapshot`: at most one a day after a main-vault unlock, only once there are transactions, last 5 kept; stored through `putBlob` so they are as encrypted as the vault), Recovery Key record (`settings.backup_recovery`), reminder state (`backupDue`: off, weekly or monthly; never on an empty vault).
- `recovery.ts`: 24 words = 256-bit entropy + 8-bit SHA-256 checksum on the BIP-39 English list (BIP-39 test vectors pinned), case/spacing tolerant, typos and bad checksums refused. `strength.ts`: offline entropy estimate with penalties for repeats, sequences and common words; a backup needs ≥ 10 characters and score ≥ 2.
- `engine.ts` + `backup.worker.ts`: `directEngine` (Vitest, the worker itself) and `workerEngine` (one-shot worker per seal/open/pack/unpack, `terminateBackupWorkers` on lock/wipe).
- UI `src/features/backup/BackupScreen.tsx` (`#/backup`): last backup + reminder, the no-backdoor warning, passphrase + strength meter, Recovery Key sheet (show, print on A5 via `PrintPortal`, verify 3 random words), create (`deliverFile`: Android cache + share sheet then delete; web share or download), restore (file → passphrase or 24 words → preview with counts → Replace or Smart Merge), snapshot list with Restore. Wired from the More "Backup" tile, the Security Center "Last backup" row and a dashboard reminder pill (main vault only).
- Decoy sessions back up and restore only the decoy's own database (the open vault); nothing reads the real vault. Auto-snapshots run only for the main vault.
- Tests: `tests/backup.test.ts` (all 26 stores + 2 blobs on both adapters: backup → wipe → restore deep-equal; SQL ↔ web both ways; safety snapshot round trip; a failing restore leaves rows and blobs unchanged; merge dedup/renumber/rebalance; snapshots roll; 15 tamper/secret cases incl. bit flips in salt, Argon2 t, slot count, wrapped key, nonce, ciphertext, tag, magic, version, truncation; Recovery Key vectors; strength; reminders), `tests/e2e/backup.spec.ts` (fa RTL full journey + en LTR layout).

## Decisions log
- **Vite 6, Capacitor 7** (spec locks). `base: './'` for Capacitor + any static sub-path.
- **Service worker web-only**; the APK ships assets in the binary.
- **Dev CSP strip** (serve only). Production and E2E always carry the CSP.
- **`'wasm-unsafe-eval'`** added to `script-src` for hash-wasm. The alternative (pure-JS Argon2) would be ~10× slower at 64 MiB.
- **Staged transactions** instead of native DB transactions held open across awaits: IndexedDB auto-commits when WebCrypto yields, and the Capacitor bridge is async. Atomicity comes from a single batch per tx.
- **Android PIN path** derives the KEK in the JS worker (one Argon2 implementation, tested against RFC 9106 via Node's OpenSSL), and native only unwraps.
- **SQLCipher 4.10.0** (not 4.20) because 4.20 needs Kotlin stdlib 2.2 / androidx.sqlite 2.7, newer than Capacitor 7's toolchain.
- **androidx.biometric 1.1.0** (latest stable; 1.4 is still RC).
- **Decoy vault**: web/iOS only (Settings hides it on Android with an honest "later version" note). Android needs a second native key slot + DB file. Inside a decoy session the security controls are hidden.
- **Web biometrics = WebAuthn PRF only.** The passkey's PRF secret is a real second KEK (`method: 'prf'` slot). Platforms without PRF get PIN-only; a UI-only biometric gate is never offered.
- **Re-auth** lasts 60 s after any unlock or PIN check; gates card/Sheba reveal and copy, auto-lock changes, decoy setup, wipe toggle and Wipe All Data. On Android `verifyKek` checks the PIN without reopening the DB; the biometric-enrolment DEK copy now exists only on explicit request.
- **E2E Argon2**: the `--mode e2e` build lowers Argon2 to m=1 MiB/t=1 via `vaultService.useArgonParamsForTesting`; `check-prod.mjs` fails if that call ships.
- **Recurring**: each occurrence posts through `postLinkedTransaction` with id `<rule>@<scheduled ms>`, so catch-up, re-runs and "Pay now" can never double-post. Catch-up is capped at 400 per rule.
- **Sayad ID**: shape-only validation; the Central Bank publishes no checksum.
- **Bank SMS senders / Android packages**: left empty, never guessed (PROMPT.md §1.4).
- **Icons**: PWA icons and Android launcher (adaptive vector + legacy PNGs) all come from `public/icons/icon.svg` (Phase 9).
- **SMS bank detection by name keywords, never by sender**: banks.json senders and packages stay empty. A sender the user confirms in the Inbox is stored in the vault (`settings.sms_senders`) and used from then on.
- **SMS inbox and sender map live in `settings` rows** (encrypted like every record) instead of new stores, so no schema or migration change was needed.
- **Every captured SMS is `pending_review`**: nothing auto-posts, even at confidence 1. Approving teaches merchant to category.
- **Taught rules are plain `sms_parser_rules`** (`is_custom`, `verified: true`), tried before templates; a rule bound to a sender only matches that sender.
- **Android SMS switches in SharedPreferences**: they are booleans and package names, not financial data, and the receiver needs them without the DEK.
- **Restricted Settings detection** = Android 13+ and the installer is not a store. Shown as a 2-step guide; it cannot be bypassed in code.
- **Charts are hand-written SVG** (Phase 6): a chart library would add 100–300 kB for six chart types, and most fight the CSP or RTL (inline styles, canvas text). The SVG mirrors with `-scale-x-100` in RTL and keeps all text in HTML, so Persian shaping stays native.
- **Analytics rows are read on the UI thread, aggregated in the worker**: the adapters decrypt where the DB handle lives; the worker gets plain rows (bigint survives structured clone) and returns the report. It re-runs on every `rev`.
- **Health Score and insights skip history the vault does not cover** instead of treating earlier months as zero spending, so a new vault never shows a fake trend or "+300 % vs average".
- **Budget `custom` period** = the user's calendar month until the schema gains start/end columns.
- **Invoice rounding** = half-up per line extension and once for VAT; nothing else rounds (Phase 7). Per-line VAT was rejected: it makes the VAT total depend on how lines are split.
- **One payment id per partial payment** (`<invoice>#<n>`): `postLinkedTransaction` allows one live tx per linked id, so partial payments need distinct ids; the repeat guard still holds because a settled invoice returns its last payment.
- **Attachment blobs outside the row stores** (Dexie v2 `blobs`, SQL migration 2 `vault_blobs`): rows stay small for `find()` scans, and the blob is written before its row, so a crash leaves at most an orphan blob, never a row without bytes.
- **Printing uses the WebView's own engine** (HTML/CSS `@page`; AirPrint on iOS, PrintManager on Android) instead of building PDFs in JS: native Persian shaping, vector text, no PDF library. The print copy is a hidden portal that exists while a document screen is open, so `window.print()` needs no state change mid-call.
- **Thermal Persian = raster**: ESC/POS code pages cannot shape Arabic script, so the thermal template is rendered to 1-bit at the printer's dot width and sent with GS v 0.
- **QR library uqr** (tiny, MIT, no deps) rendered as SVG paths; the QR carries plain text, never a URL.
- **`.arizo` = one random file key + key slots** (Phase 8): the passphrase slot (Argon2id at `ARGON2_DEFAULT`) and an optional Recovery Key slot (HKDF, 256-bit entropy needs no stretching) unwrap the same key, so one file opens with either. The header is the GCM AAD instead of a separate MAC.
- **gzip via `CompressionStream`**: built into every target WebView/Safari; no zip library.
- **Recovery Key is stored in the vault** (`settings.backup_recovery`) so every later backup gets a recovery slot without re-typing the words; it is as protected as the vault itself and never leaves it except as a wrapped slot. Turning it off soft-deletes the row.
- **Local snapshots are gzip only inside the vault blob store**, not a second passphrase layer: they never leave the device and the blob store already encrypts (web AES-GCM, Android SQLCipher).
- **Smart Merge tie rule**: equal `updated_at` keeps the local row; skipped transfer halves are reported by `verifyLedger`, not auto-dropped (documented shortcut in `restore.ts`).
- **Nested and concurrent transactions share one batch** (Phase 9): without async context a concurrent caller cannot be told from a nested one, so both join; the outer commit waits for all joiners, and a joiner that outlives the outer fn settles with the commit. Callers arriving during the batch write run afterwards in their own transaction.
- **Stress thresholds are CI-realistic, not a phone benchmark**: p95 ≤ 2 frames at 60 Hz in headless Chromium; workers timed post → result with the worker warm. Real-device numbers are still to be measured.
- **Console dropped at build time** (esbuild `drop`) rather than wrapping libraries: covers Dexie, React Router, exceljs and i18next in one place; the two residues are not `console.x(` calls and are counted by `check-prod.mjs`.
- **Device bug after Phase 9 (fixed)**: `ArizoSqlCipherPlugin.open` ran `PRAGMA secure_delete = ON` through `execSQL`; SQLCipher's `execSQL` throws for any statement that returns a row, so every open failed and on a phone the PIN never unlocked (and biometrics could never be enrolled). All PRAGMAs now go through `rawQuery` (pinned by `tests/android-native.test.ts`), the lock screen and onboarding show `lock.failed` instead of a silent pad, `openNative` re-seeds categories idempotently, and `MainActivity` fires pause/resume through a guarded `bridge.eval` (the first `onResume` ran before Capacitor existed and threw). Lesson: the Phase 9 audit compiled native code but never ran it; `android-smoke.mjs` now runs it.
- **exceljs only in a worker**: it is ~0.9 MB, so it lives in `xlsx.worker` alone; the main bundle grew ~97 kB (30 kB gzip) for all of Phase 7.
